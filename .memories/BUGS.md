# BUGS
> Дефекты и открытые вопросы. Last updated: 2026-09-07.

## Открытые

- `[BUG]` Первая подготовка после старта сервера может занять заметно дольше 4,5 с (прогрев CUDA/NVENC
  и загрузка машины). Симптом: карточка долго в состоянии «processing». Не воспроизвелось на 2–4 клипах.
  Смягчение: при (пере)открытии WS список файлов перечитывается.
- `[BUG]` Шрифты: сборка ffmpeg BtbN пишет «Fontconfig error: Cannot load default config file», но текст
  через libass рендерится (Arial из системы). На Linux нужны `fonts-liberation` или другой Arial-заменитель.

## Закрытые

- `[DONE]` 07.09.2026: сведения о файле вылезали за карточку в плитке — строка теперь одна,
  с многоточием, а в узких видах без кодека.
- `[DONE]` 07.09.2026: превью оставалось чёрным до первой перемотки — `render` только читал источники,
  а создавал их лишь `sync`. Теперь `setSource` и `attach` вызывают `sync`.

- `[DONE]` 07.09.2026: в exe `cc()` не открывал встроенный `peaks.c` по пути `B:/~BUN/root/...` (TinyCC читает
  только настоящие файлы). Решение: импорт `with { type: "text" }` и запись во временную папку перед компиляцией.

## Отложенные вопросы

- На наезде двух элементов дорожки содержимого блок правого рисуется поверх левого, и левый выглядит
  обрезанным. В экспорте всё верно, но глазами наезд не читается.
- NVENC на машине сейчас недоступен: сборка ffmpeg 9.0.1 требует драйвер NVIDIA 610+ (nvenc API 13.1),
  установленный даёт 13.0. Приложение честно откатывается на libx264.

- Наложение с поворотом в превью рисуется через canvas `rotate`, в экспорте — фильтром `rotate`.
  Совпадение по краям не проверялось попиксельно.
- Экспорт проверялся на libx264; тот же граф на NVENC после переработки не гонялся.

- Экспорт клипов без звука проверен только тестом аргументов (`aevalsrc`), на реальном файле нет.
- `loudnorm` в один проход даёт грубую нормализацию; для точной нужен двухпроходный режим.
