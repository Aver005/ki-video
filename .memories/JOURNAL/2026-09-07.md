# 07.09.2026 — старт проекта, техно-демо

## Разведка

- Bun 1.3.14 на машине. Отчёт по документации: нативного окна нет; `--compile` с `--windows-hide-console`,
  HTML-импорты внутри exe (с 1.2.17), `cc()` на Windows x64 (без `#include` стандартных заголовков).
- ffmpeg 8.1 (BtbN gpl) в `E:/Apps/ffmpeg/n81/...`: NVENC h264/hevc, CUDA, libass, afftdn, loudnorm, zoompan.
- Исходники: `E:/Videos/Counter-strike 2/*.mp4`, HEVC 1728×1080@60, AAC 48 кГц, ~30 с, ~25 МБ.
- Расширения HEVC в системе нет, значит прокси обязателен.

## Проверки до кода

- Граф `crop(x,y по t) → scale → ass → drawtext` с NVENC: 2 с на 2-секундный отрезок, кириллица есть.
- `sendcmd` на `crop w/h` — segfault. Заменено на `zoompan` с `it`: 120 кадров за 1,6 с.
- Полный граф из `buildExportPlan` на реальных файлах: exit 0, 3 с на 3 с вывода.

## Смоук через Playwright

Импорт по пути → подготовка 4,5 с → два клипа на таймлайне → ключи 2 с (1×) и 5 с (2×, сдвиг вправо) →
быстрый пресет → текст «ЛУЧШИЙ МОМЕНТ» → три реплики → воспроизведение → экспорт 60 с за 33,6 с.
Кадры выходного файла совпадают с превью.

## Починено по ходу

- Сетка `1fr` растягивалась по содержимому и прятала таймлайн: `minmax(0, 1fr)` и `min-height: 0`.
- Обратные слэши в `ki.config.json` ломали JSON: перешли на прямые, добавили понятную ошибку.
- DOM-типы перекрывали `ReadableStream` Bun: два tsconfig.
- Heredoc через Bash на Windows обрывался на длинных файлах: исходники писались инструментом Write.

## Exe

`bun run build` → `dist/ki-video.exe` 94 МБ. Запуск с `KI_NO_WINDOW=1`: статус ok, страница 200, подготовка
клипа 4,2 с. Первый прогон показал «peaks ts»: TinyCC не открыл `B:/~BUN/root/peaks-*.c`. Починено через
`type: "text"` + временный файл, второй прогон — «peaks C».

## Осторожно

При остановке dev-сервера через `Stop-Process` по имени `bun` и времени старта могли попасть чужие процессы bun
другого агента. Дальше гасить только по PID из `$!` или по имени `ki-video`.

## Ревью тремя агентами и правки

- Сервер (19 замечаний, 8 существенных): обход пути через `:id` → проверка формата id и наличия файла;
  нет проверки `Host`/`Sec-Fetch-Site` → `http/guard.ts` на всех маршрутах; гонка «один экспорт» → слот
  занимается до первого await; пик −32768 переполнял байт → clamp в C и TS; `Bun.isStandaloneExecutable`
  в 1.3.14 не определён → `Bun.embeddedFiles.length`; удаление файла во время подготовки → AbortController;
  `assets.json` пишется через tmp+rename по очереди; 416 для невыполнимых Range; чётная высота прокси.
- Общий код (13, 2 существенных): выражение до первого ключа экстраполировало → обёртка `if(lt(t,t0),v0,…)`;
  граф в аргументах мог превысить 32 767 символов → `-filter_complex_script graph.txt`; `crop … exact=1`;
  чётное окно в `baseWindow` общее для превью и экспорта; `hvc1` по кодеку; эпсилон ключей 8 мс.
- Интерфейс (18, 6 существенных): клик по клипу гасился родительской дорожкой → `stopPropagation`;
  перемотка при воспроизведении → `seek` через плеер; отмена после жеста → снимок до начала жеста;
  селектор `?? []` → стабильная константа; сохранение при закрытии вкладки (`pagehide`, keepalive);
  горячие клавиши по `e.code`; отдельный `Playhead`; компоненты по одному на файл.
- Итог: 46 тестов, повторный смоук: выделение, перемотка при воспроизведении, экспорт 17 с за 9,7 с.

## Потеря данных по своей вине

кэш в корне проекта вместе с тестовым проектом и первым экспортом. Данные пересозданы. Урок: `cd` и `rm`
только в одной группе `&&`, без `;` после.

# 07.09.2026 (вечер) — дорожки, наложения, картинки и звук

## Что просили

Разбор четырёх претензий владельца: маленькая правая панель, нельзя растягивать текст, непонятно как
добавить картинки, нужна одна большая содержательная дорожка. Выбраны дорогие варианты: полноценные
наложения и настоящий таймлайн со свободным размещением.

## Модель

`Project.version = 2`: `tracks[]` вместо `clips[]`, элементы с `start`/`duration` на общей шкале,
у медиа — `offset` внутри исходника. `shared/normalize.ts` разбирает любой входящий JSON и переносит
версию 1 (клипы подряд → элементы, `texts[]` → элементы дорожки наложений). Серверная проверка формата
свелась к этому же разбору.

## Экспорт

База собирается из кусков дорожки содержимого: зазор → `color=black`, наезд → `xfade` со смещением
`covered - overlap`, иначе `concat`. Проверено на бумаге и тестом, что раскладка совпадает с таймлайном:
после `xfade` накопленная длина равна концу правого элемента. Цветокор — один раз на готовую ленту.
Наложения идут `overlay` с `enable` и альфой, звук всех дорожек — `adelay` + `amix=normalize=0`.

## Найдено по ходу

- `-filter_complex_script` убрали в ffmpeg 9 (на машине уже n9.0.1): «Unrecognized option». Перешли на
  `-/filter_complex graph.txt` — эта запись есть с 7.0. Требование к версии поднято в README.
- `probe` бросал ошибку на файлах без видеодорожки, поэтому mp3 не импортировался в принципе.

## Проверки

- `bun run check`: типы чистые, 58 тестов зелёные. `oxlint` и `oxfmt --check` чистые.
- Живой ffmpeg: собран проект из наезда `slideleft`, зазора, картинки в кадре, повёрнутого
  полупрозрачного наложения с фейдами, текста, субтитра и музыки. Экспорт 8,5 с за 3,5 с,
  на выходе 1080×1920@60 h264+aac. Кадры 1 / 2,7 / 6 / 7 с посмотрены глазами: наложение, текст,
  субтитр, переход, чёрный зазор и картинка на месте.

## Не проверено

Интерфейс в браузере после переработки не гонялся.

# 07.09.2026 (поздний вечер) — ключи наложений и цвета, медиатека, смоук интерфейса

## Ключи

Механика ключей была написана только под окно кадра. Вынес её в `shared/keys.ts` (интерполяция по любым
числовым полям, upsert/remove/find, точки для выражений) и переиспользовал трижды: кадр, геометрия
наложения, цветокор. Ключ — снимок всего состояния, как и раньше у кадра.

В экспорте анимация идёт выражениями: положение — в `overlay=x/y` через собственные `w`/`h` наложения
(центр держится сам при любом размере), размер — `scale=eval=frame`, поворот — `rotate=a='...'`,
прозрачность — `geq` по альфе, цвет — `eq` с `eval=frame`.

## Что нашлось на живом ffmpeg

- `ow=hypot(iw,ih)` без кавычек ломает разбор фильтра: запятая внутри значения.
- `rotate=c=none` не заливает фон и не чистит буфер: при меняющемся угле кадры накапливаются, и
  прямоугольник на экране превращается в круг. Увидел на кадре, заменил на `c=black@0`.

## Что нашлось в браузере

Превью было чёрным до первой перемотки: `render` только читал источники из карты, а создавал их
`sync`, который вызывался лишь из `seek` и цикла воспроизведения. Теперь `sync` зовут `setSource` и
`attach`.

Прогон целиком: импорт трёх видов файлов, элементы на дорожках, перенос между дорожками с прилипанием,
растягивание за край, наезд с прижатием к половине, ключи наложения и цвета, виды медиатеки, ширина
панели, экспорт из панели за 2,8 с. Кадры выходного файла проверены глазами.

## Попутно

NVENC на машине отвалился не из-за кода: сборка ffmpeg 9.0.1 требует драйвер NVIDIA 610+, стоит
старее. Приложение честно откатывается на libx264.

## Не проверено

- Нативное перетаскивание файла из медиатеки на дорожку: Playwright такой перенос не воспроизводит,
  обработчик проверен синтетическим событием `drop`.
- Тот же граф на NVENC и сборка exe.

# 07.09.2026 (ночь) — отдаление, карточки, конфиг рядом с exe

## Отдаление

Зум держался в диапазоне 1..8, то есть кадр нельзя было отвести дальше базового окна. Обобщил
цепочку: окно режется по самому дальнему плану `far = min(1, zoom)`, а `zoompan` приближает от него
(`z = zoom / far`). Когда окно шире исходника, перед `crop` встаёт `pad` с чёрным холстом. При
`far = 1` цепочка та же, что была, — старые тесты не тронулись.

Предел `MIN_ZOOM = 0.2` выбран по холсту: он растёт как 1/zoom, и на 0.1 у горизонтального исходника
вышло бы 6060×10800. Появление «из точки» делается не отдалением базы, а наложением: минимальная
ширина наложения снижена до 0.005 кадра, в выражении масштаба поставлен пол в два пикселя.

Проверено на живом ffmpeg: кадр 0.2 → 1 и наложение 0.01 → 1.2 за 4 секунды, экспорт 2,4 с,
кадры на 0,1 / 2 / 3,9 с посмотрены глазами — исходник едет из глубины с чёрными полями, точка
вырастает в прямоугольник.

## Карточки медиатеки

Сведения о файле вылезали за карточку в плитке. Строка теперь одна, с многоточием, у карточки
`overflow: hidden`, а в плитке и в строке кодек не показывается — он всё равно виден в подсказке.

## Сборка

`bun run build` кладёт рядом с exe `ki.config.json` (если он есть в корне) и `ki.config.example.json`.
Проверено: exe 94,2 МБ, оба файла в `dist`.
