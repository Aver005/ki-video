# DECISIONS
> Решения с причинами. Last updated: 2026-09-07.

- `[DECIDED]` **Bun + браузерный интерфейс, ffmpeg как внешний процесс.** Bun даёт сервер, бандлер, тесты
  и `--compile` без зависимостей. Кодеки писать самим бессмысленно.
- `[DECIDED]` **Окно — Edge/Chrome `--app`.** Проверено по документации Bun 1.3.14: нативного окна нет,
  `Bun.WebView` умеет только headless. WebView2 через FFI — отдельная задача.
- `[DECIDED]` **Прокси H.264 720p всегда.** Исходники ShadowPlay в HEVC, в Chromium без расширения HEVC
  не играют. Прокси делает NVENC за ~3 с на 30 с клипа.
- `[DECIDED]` **Зум через zoompan после crop.** `crop` меняет w/h только через `sendcmd`, а это в ffmpeg 8.1
  падает с segfault (проверено). `zoompan` с `it` работает.
- `[DECIDED]` **React без UI-библиотек, стор на `useSyncExternalStore`.** Минимум зависимостей по
  требованию владельца; логика в `actions.ts`, компоненты только UI.
- `[DECIDED]` **Пики звука на C через `cc()`** как проба возможностей Bun; TS-путь остаётся запасным
  и эталонным в тестах. Исходник без `#include`, чтобы не зависеть от заголовков TinyCC на Windows.
- `[DECIDED]` **Пути в `ki.config.json` через прямые слэши.** Обратные ломают JSON.
- `[DECIDED]` **Один проект на приложение.** Для демо достаточно; менеджер проектов позже.
- `[DECIDED]` **Диалог файлов через PowerShell `OpenFileDialog`.** Нативно для Windows, без пакетов.
  В Docker и на Linux — просмотр папок через `/api/fs`.
- `[DECIDED]` **Граф ffmpeg передаётся файлом** (`-/filter_complex graph.txt`): командная строка Windows
  ограничена 32 767 символами, а каждый ключевой кадр даёт до 7 повторов выражения.
  `-filter_complex_script` убрали в ffmpeg 9, запись `-/opt file` работает с 7.0 — она и осталась.
- `[DECIDED]` **Локальный сервер защищён от чужих страниц**: Host только локальный, изменяющие запросы только
  с `Sec-Fetch-Site: same-origin`. Иначе любая вкладка могла бы запускать ffmpeg по своим путям.

## Модель дорожек (07.09.2026)

- `[DECIDED]` **Проект версии 2: дорожки и элементы со свободным размещением.** `Track {kind, items}`,
  где kind — `content` (база кадра), `overlay` (наложения и текст), `audio` (музыка). Элемент —
  `MediaItem` или `TextItem` с `start` и `duration` на общей шкале. Старый `clips[]` переносится
  в `core/normalize.ts`; он же чистит любой входящий JSON, поэтому отдельной проверки формата нет.
- `[DECIDED]` **Наезд элементов и есть переход.** Отдельной сущности перехода нет: перекрытие двух
  элементов дорожки содержимого даёт `xfade` длиной в перекрытие, тип берётся у правого элемента.
  Тот же наезд превращается в `afade` на обоих звуках. Перетаскивание не даёт наехать больше чем
  на половину короткого элемента (`clampContentStart`).
- `[DECIDED]` **Композиция экспорта: лента + наложения.** База — куски дорожки содержимого, склеенные
  `concat`, с `color=black` в зазорах и `xfade` на наездах; цветокор применяется один раз к готовой
  ленте. Наложения идут `overlay` с `enable`, прозрачностью через `colorchannelmixer=aa` и
  `fade ... :alpha=1`. Звук всех дорожек — `adelay` + `amix=normalize=0`. Текст и субтитры остаются
  одним ASS поверх всего.
- `[DECIDED]` **Один вход ffmpeg на элемент таймлайна.** Тот же файл в трёх местах — три входа с
  разными `-ss/-t`. Проще, чем делить поток, и заметно быстрее не станет.
- `[DECIDED]` **Картинка не имеет длительности.** У ассета `duration = 0`, длину задаёт элемент;
  вход `-loop 1 -framerate N -t D`. Кадрирование, ключи и зум работают как у видео.
- `[DECIDED]` **Звуковые файлы — отдельный вид ассета.** `probe` больше не требует видеодорожки,
  подготовка делает `proxy.m4a` и пики, ассет ложится только на звуковую дорожку.
- `[DECIDED]` **Размеры панелей живут в `localStorage`.** Ширина медиатеки и инспектора, высота
  таймлайна и вид медиатеки — свойство рабочего места, а не проекта.

## Ключевые кадры (07.09.2026)

- `[DECIDED]` **Одна механика ключей на всё** (`src/shared/keys.ts`): ключ хранит полное состояние
  плюс `t`, интерполяция линейная по всем числовым полям. Так работают окно кадра, геометрия
  наложения (`boxKeys`, время от начала элемента) и цветокор (`colorKeys`, время от начала проекта).
  Отдельного времени у каждого поля нет: ключ ставится снимком, как в окне кадра.
- `[DECIDED]` **Анимация наложения — выражениями ffmpeg, а не покадровой сборкой.** Положение идёт
  в `overlay=x/y` через собственные `w`/`h` наложения (центр держится сам при любом масштабе),
  размер — `scale=eval=frame`, поворот — `rotate=a='...'`. Проверено на живом ffmpeg.
- `[DECIDED]` **Поворот заливается `c=black@0`, а не `c=none`.** `c=none` не чистит буфер: при
  меняющемся угле кадры накладываются друг на друга и прямоугольник превращается в круг (видели).
  Выражения с запятыми (`hypot(iw,ih)`) обязательно в кавычках, иначе разбор фильтра падает.
- `[DECIDED]` **Прозрачность по ключам — через `geq`.** `colorchannelmixer` постоянен, `fade` умеет
  только вход и выход. `geq` считает попиксельно и стоит дорого, поэтому включается только когда
  прозрачность действительно меняется.
- `[DECIDED]` **Отдаление кадра — через чёрный холст `pad` перед `crop`.** Окно кадрирования режется
  по самому дальнему плану (`min(1, zoom)`), а `zoompan` дальше только приближает: `z = zoom / far`.
  Когда окно шире исходника, исходник кладётся на холст нужного размера. Предел `MIN_ZOOM = 0.2`:
  холст растёт как 1/zoom, при 0.1 у горизонтального исходника получилось бы 6060×10800.
  Появление «из точки» делается наложением, а не отдалением базы: там масштаб идёт от 0.005 кадра.
- `[DECIDED]` **Цветокор по ключам — только `eq` с `eval=frame`.** Сочность (`vibrance`) и резкость
  (`unsharp`) выражений по времени не принимают и остаются постоянными; в панели это написано.

## Иконки интерфейса (07.09.2026)

- `[DECIDED]` **Иконки — `lucide-react`, а не символы Unicode.** Глифы (`▶`, `👁`, `📁`, `◆`) зависели
  от шрифта системы: разный размер, разная толщина, эмодзи цветные. Пакет добавлен сознательно, в
  обход прежнего запрета на зависимости; Bun вытрясает неиспользуемое (в exe есть `skip-back`,
  `volume-2`, `layout-grid`, нет `anvil`, `biohazard`, `wand-sparkles`).
- `[DECIDED]` **Размер иконки задаётся стилем, а не свойством `size`.** В `layout.css` правила для
  `.lucide` внутри `.btn`, `.btn--small`, `.btn--icon`, `.asset__kind`; в разметке иконка ставится
  без свойств. Иначе размер пришлось бы повторять в двадцати с лишним местах.
- `[DECIDED]` **`.btn` стал `inline-flex` с `gap: 6px`.** Иконка и подпись — два элемента подряд,
  без пробелов-разделителей в разметке.

## Интерфейс на shadcn/React Aria и FSD (07.09.2026)

- `[DECIDED]` **Берём официальный shadcn с базой React Aria, а не jolly-ui и не Intent UI.**
  С июля 2026 React Aria — штатная база shadcn наравне с Base UI и Radix (`init --base aria`,
  реестр `https://ui.shadcn.com/r/styles/aria-nova/<имя>.json`). Сторонние наборы дублируют её и
  висят на одном мейнтейнере.
- `[DECIDED]` **`shadcn init` не используем: он умеет только шаблоны проектов (next, vite, astro).**
  `components.json` написан руками, компоненты ставятся через `shadcn add`.
- `[DECIDED]` **`paths` лежат в `tsconfig.json`, а не в `tsconfig.base.json`.** CLI shadcn читает
  только корневой `tsconfig.json` и по `extends` не идёт: с алиасами в базовом файле он не находит
  проектных путей. `tsconfig.app.json` теперь наследует `tsconfig.json`, дублирования нет.
- `[DECIDED]` **`cn` — пакет npm от самого shadcn, а не свой `lib/utils.ts`.** Реестр объявляет его
  в `dependencies`; репозиторий `shadcn-ui/cn`, ноль зависимостей, замена `clsx` + `tailwind-merge`.
- `[DECIDED]` **`tailwindcss` прибит к 4.1.14 — ровно к версии движка внутри `bun-plugin-tailwind`.**
  Плагин везёт свой Tailwind внутри `index.mjs` (1,5 МБ), а таблицы стилей тянет из `node_modules`.
  С 4.3.3 в баннере собранного CSS стояло 4.1.14: движок и таблицы разъезжались.
- `[DECIDED]` **`exactOptionalPropertyTypes` выключен только для программы интерфейса.**
  `react-aria-components` не совместим с этим флагом (6 ошибок в `select`, `progress`, `input-group`
  сразу после установки); наш код при передаче свойств в RAC упирается в то же самое.
  Сервер и `core` проверяются с флагом через `tsconfig.json`.
- `[DECIDED]` **`src/shared` переименован в `src/core`.** Имя `shared` отдано слою FSD. `core` —
  изоморфный домен, его видят и сервер, и интерфейс; 121 импорт в 53 файлах правился скриптом
  с сухим прогоном.
- `[DECIDED]` **Старый CSS втянут в `globals.css` через `layer(base)` и `layer(components)`.**
  Без слоёв неслоёный `layout.css` бьёт любые утилиты Tailwind (правило `button, input { font: inherit }`
  ломало бы размеры шрифта у компонентов shadcn). Теперь утилиты выигрывают, а старые правила
  доживают до переноса своего компонента.
- `[DECIDED]` **Виджеты получают действия свойствами из `App.tsx`.** `store/actions.ts` лежит в слое
  app, снизу его не видно. Пока он не разобран на entities и features, инъекция сверху — единственный
  способ не заводить импорт вверх по слоям.
- `[DECIDED]` **Старая палитра переименована в `--ki-*`.** Имена `--muted`, `--accent`, `--radius`
  были и в `theme.css`, и в токенах shadcn; блок `.dark` перебивал `:root`, из-за чего `.muted`
  красил текст цветом тёмной подложки и подписи панелей пропадали. Найдено глазами при смоук-тесте,
  подтверждено `getComputedStyle`. Префикс получили все 14 переменных, чтобы следующее столкновение
  не пришлось искать заново.
- `[DECIDED]` **Подсказки на кнопках, которые бывают отключены, — нативный `title`, а не `Tooltip`.**
  `TooltipTrigger` оборачивает первого ребёнка в `Focusable`, а отключённая кнопка не фокусируется:
  три предупреждения в консоли. Документация shadcn предлагает обёртку `<span>`, но у активной
  кнопки это даёт лишнюю остановку табуляции. RAC не пропускает `title` через свои компоненты
  (свойства фильтруются), поэтому в `TransportBar` заведён локальный `Hint`: `<span title>` вокруг
  кнопки. `Tooltip` из набора остаётся для мест, где кнопка всегда активна.

## Ползунки и числовые поля (07.09.2026)

- `[DECIDED]` **Ползунок — свой составной `SliderField` поверх `shared/ui/slider`.** Ряд собирает
  подпись, шкалу с делениями и числовой ввод. Своё лежит в `src/shared/ui/kit/`, файлы из реестра —
  в корне `src/shared/ui/`; из-под `oxfmt` выведен только корень (`src/shared/ui/*.tsx`).
- `[DECIDED]` **Засечки: восемь равных делений плюс высокая метка опорного значения.** Опорные
  берутся из домена, не выдумываются: `NEUTRAL_COLOR`, `DEFAULT_BOX`, `defaultFrame(asset)`,
  громкость 1, фейды 0, `SILENT_AUDIO.denoise`, высота субтитров 0.8. Где опорного нет (кегль,
  качество) — метки нет.
- `[DECIDED]` **Прилипание к опорному значению работает только при перетаскивании мышью.**
  Окно ±2 % шкалы, то есть ~4 пикселя дорожки при любой шкале: значение отображается на пиксели
  линейно, отдельная пиксельная мера не нужна. С клавиатуры прилипания нет — иначе шаг стрелкой
  рядом с нейтралью возвращался обратно и значения около неё становились недостижимы.
- `[DECIDED]` **Признак перетаскивания ловится на фазе перехвата (`onPointerDownCapture`).**
  react-aria гасит `pointerdown` на цели, до делегированного обработчика React на обёртке событие
  не доходит — прилипание молча не срабатывало. `onKeyDownCapture` сбрасывает признак.
- `[DECIDED]` **Числовое поле — `NumberField` из react-aria-components, без своего черновика.**
  RAC сам отдаёт значение на blur, Enter и стрелках, а не на каждую букву; клампинг по min/max,
  шаг и разбор по локали — его же. Старый ручной черновик удалён.
- `[DECIDED]` **Локаль задана явно: `I18nProvider locale="ru-RU"` в `main.tsx`.** Иначе RAC берёт
  язык браузера и разделитель дробной части плавает от машины к машине. Числа теперь везде с
  запятой — как уже было в полях `input[type=number]` до правки.
- `[DECIDED]` **Собственный формат значения заменён на `unit`.** Было два применения: `×` у зума
  (стал `unit="×"`) и `CQ ` у качества (ушло в подпись «Качество, CQ»). Произвольная функция
  форматирования несовместима с полем, в которое можно печатать.
